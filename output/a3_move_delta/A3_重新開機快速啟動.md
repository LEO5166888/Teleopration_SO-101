# A3 重新開機快速啟動

適用情況：Mac 已重新開機、RTXWS／VS Code 連線已中斷、`isaac-sim` 容器停止，但 A3 程式先前已部署並通過 Thomas App 驗收。

日常重新啟動不需要重新 `scp`、`docker cp` 或安裝 `flatdict`。總共要保留三個持續執行的程序：

1. RTXWS Docker 裡的 Isaac Sim／A3 server。
2. Mac 的 SSH tunnel。
3. Mac 的 phone relay。

資料通路：

```text
Thomas App
  -> ws://<Mac Wi-Fi IP>:8765
  -> Mac phone relay
  -> Mac 127.0.0.1:8766
  -> SSH tunnel
  -> RTXWS Docker 127.0.0.1:8766
  -> Isaac Sim SO-101
```

## 1. 啟動 Docker［VS Code 的 RTXWS Terminal］

先用 VS Code Remote SSH 連到 RTXWS，開啟 Terminal。提示字元必須類似：

```text
leo@RTXWS:...$
```

查看容器狀態：

```bash
docker ps -a --filter name=isaac-sim
```

如果狀態是 `Exited`，執行：

```bash
docker start isaac-sim
```

如果狀態已是 `Up`，不用再 `docker start`。接著進入容器：

```bash
docker exec -it isaac-sim bash
```

成功後提示字元會變成：

```text
root@RTXWS:/isaac-sim#
```

## 2. 啟動 Isaac Sim 與 A3 server［Docker Terminal］

在剛才的 `root@RTXWS` 容器終端機完整貼上：

```bash
cd /root/Documents/robotics/upstream/leisaac/dependencies/IsaacLab

PYTHONPATH="/root/Documents/robotics/upstream/leisaac/dependencies/IsaacLab/source/isaaclab:/root/Documents/robotics/upstream/leisaac/dependencies/IsaacLab/source/isaaclab_assets:/root/Documents/robotics/upstream/leisaac/dependencies/IsaacLab/source/isaaclab_tasks:/root/Documents/robotics/upstream/leisaac/source/leisaac${PYTHONPATH:+:$PYTHONPATH}" \
CUDA_VISIBLE_DEVICES=0 \
PUBLIC_IP=140.115.54.63 \
LIVESTREAM=1 \
ENABLE_CAMERAS=1 \
PYTHONUNBUFFERED=1 \
./isaaclab.sh -p \
/root/Documents/robotics/work/so101_shared_autonomy/scripts/a3_move_delta/a3_sim_move_delta.py \
--livestream 1 --enable_cameras --ws-host 127.0.0.1 --ws-port 8766
```

這個終端機要保持開啟。看到以下內容才進行下一步：

```text
A3 MOVE_DELTA SIM READY
A3 WS READY ws://127.0.0.1:8766
Motion profile: coarse=90 trajectory steps, fine=23 trajectory steps, stable=5, hold_limit=90
```

黃色的 `Performance warning` 可以先忽略。若出現 Python traceback，或沒有 `A3 WS READY`，不要繼續送移動命令。

## 3. 開啟 Isaac Sim WebRTC［Mac 瀏覽器］

用先前觀看 RTXWS Isaac Sim 的 WebRTC 頁面連線。確認畫面中有 SO-101，而且手臂沒有自行持續移動。

這一步不需要在 Terminal 輸入指令。測試期間保留 WebRTC 畫面，以便確認實際移動方向。

## 4. 查 Mac 本次的 IP［Mac Terminal 1］

在 Mac 本機新開 Terminal，提示字元應類似 `lichengyan@MacBookPro ... %`：

```bash
ipconfig getifaddr en0
```

先前使用的是 `192.168.50.13`，但每次重新開機或更換 Wi-Fi 都要重新確認。假如這次仍顯示：

```text
192.168.50.13
```

Thomas App 的網址就是：

```text
ws://192.168.50.13:8765
```

若 IP 改變，請把新網址告訴 Thomas。Mac 和手機必須在可互相連線的同一個區域網路。

## 5. 建立 SSH tunnel［Mac Terminal 1］

在同一個 Mac Terminal 執行：

```bash
ssh -N -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:8766:127.0.0.1:8766 \
  leo@140.115.54.63
```

輸入 RTXWS 密碼後，畫面停在空白是正常的，代表 tunnel 正在運作。這個 Terminal 必須保持開啟，也不要在裡面輸入其他命令。

## 6. 每次啟動的 Mac 小測試［Mac Terminal 2］

再開一個 Mac Terminal，先切到正確資料夾：

```bash
cd "/Users/lichengyan/Documents/ChatGPT/碩士論文/output/a3_move_delta"
```

先向 X+ 微調 5 mm：

```bash
../a3_mac_sim/.venv/bin/python mac_move_delta.py --axis x --dir 1 --step fine
```

必須看到：

```text
A3 MOVE_DELTA X PLUS FINE PASS
```

再回到 X-：

```bash
../a3_mac_sim/.venv/bin/python mac_move_delta.py --axis x --dir=-1 --step fine
```

必須看到：

```text
A3 MOVE_DELTA X MINUS FINE PASS
```

兩個命令都通過，代表 Isaac Sim、A3 server 和 SSH tunnel 已接通。任何一條出現 `FAIL`、`rejected`、timeout 或 connection refused，都先停止，不要重複送命令。

## 7. 啟動 Thomas App relay［Mac Terminal 2］

小測試通過後，在仍位於 `a3_move_delta` 資料夾的 Mac Terminal 2 執行：

```bash
../a3_mac_sim/.venv/bin/python mac_phone_relay.py
```

正常輸出會是：

```text
MAC PHONE RELAY READY listen=ws://0.0.0.0:8765 upstream=ws://127.0.0.1:8766
Thomas App URL: ws://<本次 Mac IP>:8765
One App connection; no command buffering or automatic retry.
```

這個 Terminal 也要保持開啟。若 macOS 詢問是否允許 Python 接受連入連線，請允許區域網路連線。

## 8. Thomas App 重新連線與開機檢查

Thomas 在 App 輸入 relay 顯示的完整網址，例如：

```text
ws://192.168.50.13:8765
```

Thomas 按連線後，Mac relay 應出現：

```text
[PHONE CONNECT] peer=(...)
[RTXWS CONNECT] ws://127.0.0.1:8766
```

App 端應收到 `welcome`，接著持續收到 `state`。正式操作前最少做以下開機檢查：

1. App 按一個 fine 方向鍵，等收到最終 `ack status=ok`。
2. 按反方向回來，確認 WebRTC 中方向正確。
3. Open、Close 各一次，確認夾爪與 `state.gripper`。
4. 做一次移動中 Estop，確認手臂停止且 `state.estop=true`。
5. Estop Reset 後，確認 `state.estop=false`，再做一個 fine 移動確認控制恢復。

每次只能送一個動作，必須等該動作的最終 `ack` 才按下一個按鈕。

## 9. 哪些測試不必每次重跑

A3 已經完成正式驗收，因此每次一般重新開機不必重跑十二組 coarse/fine 六方向，也不必重新執行斷線測試。

只有在以下情況才跑完整回歸測試：

- 修改 `a3_transport.py` 或 `a3_sim_move_delta.py`。
- 重新建立或更換 `isaac-sim` 容器。
- Thomas 修改 App 的封包、按鈕映射、連線或重連邏輯。
- 開機小測試出現方向、速度、ack、Estop 或 state 異常。

完整回歸測試包含：六方向 coarse/fine、gripper open/close、Estop/reset、busy 防護及斷線自動 Estop。詳細步驟在同資料夾的 `A3_冷啟動與_Thomas_App_整合操作手冊.md`。

## 10. 正常結束順序

1. Thomas App 先斷線。
2. Mac relay Terminal 按 `Ctrl-C`。
3. Mac SSH tunnel Terminal 按 `Ctrl-C`。
4. Docker 裡執行 Isaac Sim 的 Terminal 按 `Ctrl-C`，等回到 `root@RTXWS`。
5. 在 Docker shell 輸入：

   ```bash
   exit
   ```

6. 回到 `leo@RTXWS` 後，若不再使用容器：

   ```bash
   docker stop isaac-sim
   ```

## 11. 常見問題

| 現象 | 處理方式 |
|---|---|
| `../a3_mac_sim/.venv/bin/python: No such file or directory` | 先執行第 6 步的 `cd`，確認自己在 Mac，不是在 RTXWS／Docker。 |
| `Connection refused` | 確認 Docker 端已有 `A3 WS READY`，再確認 SSH tunnel Terminal 仍開著。 |
| Relay 顯示 `[RTXWS UNAVAILABLE]` | SSH tunnel 已斷線或 `8766` 沒有正確轉送；重建 tunnel。 |
| App 連不到 `8765` | 重新查 Mac IP、確認 relay 正在執行、手機與 Mac 同網，並允許 macOS 防火牆。 |
| `Address already in use` | 已有舊 tunnel 或 relay 佔用該 port；回到舊 Terminal 停止它，避免重複啟動。 |
| Relay 出現 `[PHONE DISCONNECT]` | App 已離線；若當時正在移動，Server 會自動 Estop。重新連線後先看 `state.estop`，必要時 reset。 |
| `reason=busy` | 上一個動作還沒結束；等待原命令的最終 ack，不要重送。 |
| `position_tolerance_not_met` | 停止操作，查看 Docker Terminal 的 start／target／end／error，不要自動重試。 |
